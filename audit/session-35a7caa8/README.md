## Arithmetic and dated assumptions

`form571-2026-11-11.csv` is a manual transcription of Form 571 fetched on the review date. `test_rates_and_scenarios.py` compares all 46 start dates, end dates and rates to the canonical data and independently uses rational numbers for the following **conditional arithmetic**, without any rounding:

- Unit 1: $3,995 × 1.6% = $63.92; illustrative new rent $4,058.92. With the assumed 1.4% banked component, $119.85 and $4,114.85.
- Unit 2: the **2019 starting amount**, $3,150 × 1.6% = $50.40; illustrative new rent $3,200.40. If six specified historical rates were validly banked, 11.5% + 1.6% = 13.1%, or $412.65 and $3,562.65. The current base and no-prior-increase premise are not verified.
- Calendar subtraction is tested for the stated hypothetical effective dates and service assumptions. It is not proof that a deadline is safe, that a notice was served, or that the tenancy permits an increase. Prior increases, lease terms, license status, repair conditions and changes in the law remain unresolved.

The baseline generator uses `ROUND_HALF_UP`, though all these specific examples happen to produce exact cents. A future input could produce a fractional cent; the effect of rounding must be checked against the relevant rule rather than silently claiming no amount is rounded up. In the baseline data, Unit 2's hypothetical February 28, 2027 effective date is stored under an `anniversary` key even though the actual anniversary is not established; this was sent to the canonical owner as an issue, not silently treated as a fact.

## Source-link census and its limits

At baseline commit `fcdef50` before either live integration branch changes the site, `verify_public_rows.py --report-only` counted **503** data rows without a direct first-party link: root 17, assurance 37, hub 194, docs 222, review 16, and site 17. Dashboard's repository-status rows do have first-party GitHub repository links; the preliminary government-only census counted nine of those as missing. GitHub is an official source for repository facts, **not** for a rent-law claim. The audit accepts the exact official City `sftreasurer.org` host despite its non-`.gov` domain.

The checker uses an HTML parser, includes every current `.html` file under the Pages root (including direct-entry archives), ignores header-only rows, and requires each data row to contain its own HTTPS link to an official government/recognized City publisher or a first-party repository-information source. It deliberately does not count a nearby row, a local registry anchor, a flag anchor, a plain-text URL, or lookalike hostnames. It does not prove that the link is reachable, that its content supports the specific row, or that private facts were verified; those require separate review.

Run the independent checks:

```sh
python3 -m unittest discover -s audit/session-35a7caa8 -p 'test_*.py' -v
python3 audit/session-35a7caa8/verify_public_rows.py --canonical
python3 audit/session-35a7caa8/verify_public_rows.py
```

The two citation commands return nonzero while any scoped row lacks a direct first-party source. `--report-only` is available for a non-blocking census during remediation. No output prints the contents of a potentially sensitive historical row.
